## The 5-YAML (Entity Fact Model)

Every entity is captured as structured facts across 5 domains:

### 1. Identity
- **name:** Primary name
- **aliases:** Alternative names, nicknames
- **type:** Person / Place / Item / AI Node / Event
- **status:** active / inactive / archived / superseded
- **certainty:** confirmed / inferred / unknown / contradicted

### 2. Physical / Sensory Facts
- **appearance:** Visual description, color, size, shape
- **location:** Where it is / where it lives
- **material:** What it's made of (for items)
- **condition:** State of wear, health, functionality

### 3. Ownership / Transaction Facts
- **owner:** Who owns it
- **acquired:** When / how it was obtained
- **paid:** Price paid, currency, date
- **current_value:** Estimated current worth
- **history:** Previous owners, transactions

### 4. Operational Facts
- **purpose:** What it's for
- **capabilities:** What it can do
- **limitations:** What it can't do
- **connections:** Related entities, links, associations
- **usage_pattern:** How often, when, by whom

### 5. Dynamic / Temporal Facts
- **last_seen:** When it was last observed
- **changes:** What changed and when
- **status_history:** How its status evolved
- **relationships:** How it relates to other entities over time

## Why This Matters

The AI can only represent what it knows.
- No facts = no picture = generic responses
- Static facts = static picture (color, size, material)
- Dynamic facts = living picture (price changes, location moves, status shifts)
- Operational facts = functional picture (what it does, how it works)
- Relationship facts = networked picture (how it connects to everything else)
