# Execution Directive 012
**From:** Cell2 (analysis/proposal)  
**To:** GBG (execute on own substrate)  
**Via:** Cell1 (operator gate — approved)  
**Re:** GRIMOIRE self-cast spell gating and visual distinction  
**Date:** 2026-08-25  
**Priority:** High — operator feedback: self-casts too frequent, need visual distinction and gating

## Context
Operator feedback:
- "i want the name of the ai inside the focus to be the name of the focus" — already implemented
- "if a spell is to be generated by grimoire and it wants something inputted into itself... we need to make that spell specifically a certain color"
- "since its a self cast we should be setting up how the grimoire app is able to come up with these so its not just constantly happening. it needs to be for a good reason"

Current behavior: Spells can auto-forge from normal conversation, including self-casts targeting the focus's own AI. This creates noise and circular references.

Required change: Self-casts must be visually distinct, gated behind explicit intent, and require stated purpose.

## Execution items

### 1. Visual distinction for self-cast spells
**Current state:** All spells look the same regardless of target.

**Required change:**
- Self-cast spells (where `spell.targetNode.node_id === spell.focus_id` or target is the current focus's AI) get:
  - Unique border color: `#ff6b35` (orange) or `#ffd700` (gold) — distinct from normal spell purple
  - Badge/label: "SELF-CAST" on the spell card
  - Subtle glow or left-border accent to make them instantly identifiable
- Normal spells keep existing styling
- The visual distinction must be obvious at a glance in both the spell card and spell detail view

**Files:** `css/styles.css`, `js/app.js`, `index.html`

**Acceptance:**
- [ ] Self-cast spells have unique color/border
- [ ] "SELF-CAST" badge visible on card
- [ ] Normal spells unchanged
- [ ] Distinction visible in both card list and detail view

### 2. Gating mechanism for self-cast spell generation
**Current state:** Spells auto-forge from conversation without explicit self-cast intent.

**Required change:**
Self-casts only forge when one of these conditions is met:
- **Explicit command:** Operator types `/self-cast`, `/reflect`, or `/introspect` in chat
- **Manual forge:** Operator clicks "Forge Self-Cast" button in spell panel (new UI element)
- **Alignment threshold:** Focus density ≥ 70% AND message contains self-referential keywords ("what am i", "who are you", "my purpose", "my gaps") — but only once per session per focus to prevent spam

**Blocking rules:**
- Normal conversation does NOT trigger self-casts
- Regular spell forge defaults to external node target (from node registry)
- If no external nodes exist, show: "No external nodes configured. Add a node in Settings → Nodes, or use /self-cast for self-reflection."

**Files:** `js/app.js`, `js/data.js`, `index.html`

**Acceptance:**
- [ ] Normal chat does not auto-forge self-casts
- [ ] `/self-cast` command triggers self-cast forge
- [ ] "Forge Self-Cast" button exists in spell panel
- [ ] Alignment threshold triggers at most once per session
- [ ] Error message when no nodes exist and no self-cast intent

### 3. Purpose requirement in self-cast spells
**Required change:**
- When a self-cast is forged, the spell content must include a "PURPOSE" section that states why this self-cast is being forged
- The purpose is derived from the triggering message or operator input
- Format:
  ```
  ## PURPOSE
  [One sentence: why this self-cast is happening now]
  ```
- If purpose cannot be determined, the spell does not forge — show error: "Self-cast requires stated purpose."

**Files:** `js/app.js`, `js/data.js`

**Acceptance:**
- [ ] Self-cast spells include "## PURPOSE" section
- [ ] Purpose is derived from conversation context or operator input
- [ ] Spells without purpose do not forge
- [ ] Error toast explains missing purpose

### 4. Self-cast spell lifecycle
**Required behavior:**
- Self-cast spells go through the same cast/copy/paste cycle as normal spells
- The "reply" from the self-cast is the AI's own introspection output
- In practice: operator copies self-cast spell, pastes it into the focus's own chat as a system prompt, gets the AI's response, pastes it back
- This creates a deliberate reflection loop, not an accidental one

**Files:** `js/app.js`

**Acceptance:**
- [ ] Self-cast spells can be copied, sent, and replied to
- [ ] Reply capture works same as normal spells
- [ ] Spell status advances after reply

### 5. Preserve existing functionality
**Do NOT change:**
- Normal spell forge/cast/copy/paste cycle
- External node dispatch (clipboard/HTTP)
- Spell conditions, tier/mastery, upgrade system
- Entity/experience capture
- Intelligence Audit panel

**Only change:** How self-casts are triggered, styled, and documented.
